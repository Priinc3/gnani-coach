## 3. F02 — prose slot closed in durable metrics

**Change.** `durable-metrics.schema.json` no longer accepts free text in
`method` (was any 1–120-char string). It is now:

- `method` — closed identifier set (`$defs/methodId`): `vad_speech_regions`,
  `stt_words_over_speech_regions`, `disfluency_recognition`,
  `turn_connection_timer`. Exactly one identifier is coupled to each metric
  key. Descriptions state explicitly that **naming an identifier does not
  mean the detector is implemented or validated** — no metric has ever been
  produced in Phase 01.
- `unavailabilityReason` — closed reason codes (`stt_unavailable`,
  `speech_analysis_unavailable` with `status: unavailable`;
  `too_little_speech` with `status: insufficient_evidence`), required when
  and only when status is not `available`. `method` is required only when
  `available` and forbidden otherwise, so an unmeasured metric cannot claim
  a method was applied.

**Other durable metadata audited for prose-by-another-name.** All remaining
durable fields are already closed or pattern-bound: metricKey/unit/status
(enums), ids (`^ses|rnd|trn|rec_…$`), catalog ids (shape + runtime
membership check), date-time, numerics. The **transient**
`analysis-observation.reliability.limitations` strings remain free text by
design (evidence spans/limitations belong to the transient path); the schema
description now documents that they are trusted application output and that
authorship is a writer-boundary responsibility, not a schema check.
Display labels must be produced from trusted application mappings of the
controlled identifiers — never copied from learner or model text.

**Honesty boundary (corrected in schema descriptions, architecture docs, and
here):** schema validation closes the property-name and free-text routes,
but it cannot prove a future writer, logger, or cache respects the boundary,
and catalog membership/freshness remain runtime checks. The old claim that
the shape is "deliberately incapable of holding learner or model content"
has been replaced with an exact statement of what is and is not enforced.

## 4. F03 — metric domains and units enforced

**Change (applied identically to `durable-metrics` and transient
`analysis-observation`):**

- All values nonnegative (`minimum: 0` per metric-key rule).
- `*.count` and `*_ms` keys require **integer** values; `*_wpm` keys allow
  fractional numbers.
- Each metric key is coupled to exactly one unit: `pause.longest_ms` /
  `turn.duration_ms` → `milliseconds`; `pause.count` / `filler.count` →
  `count`; `speech.rate_wpm` / `speech.active_rate_wpm` →
  `words_per_minute`. A count cannot validate as wpm; a duration cannot
  validate as a count.
- Preserved: available zero (real measurement), fractional rates,
  unavailable/insufficient-evidence nulls with reason codes. No invented
  global "ideal" rates and no pronunciation/confidence score were added.
