## Deliverables (only what the goal needs)
1. **`CallExperience({catalog})`** (the `index.ts` export is unchanged) as the real app: onboarding → scenario → language & settings → call → coaching break → summary → history. Responsive, mobile-first. Speakify look from the tokens in `globals.css` (read-only; use the tokens, don't edit the file). Build real components, not an image of the board. Illustration: no asset exists. Use a clearly intentional original inline-SVG avatar and report the asset gap.
2. **Settings:** separate speaking-language and coaching-language selectors (from the catalog, honest capability badges), level, preset, transient Custom Topic, **recording toggle default OFF** with a plain explanation (live processing vs saved audio), and transient subtitles.
3. **Audio capture** (`lib/audio`): `getUserMedia` (HTTPS or localhost only), an AudioWorklet that downsamples to 16 kHz mono s16le and emits **1,024-byte** frames paced in real time. Source: https://developer.mozilla.org/en-US/docs/Web/API/AudioWorklet. Echo cancellation and noise suppression are constraints requested on the mic, not guaranteed. Worklet file lives in your tree and loads with a supported Next.js approach you research and cite. Mic denied or unavailable gets a plain recovery state.
4. **Transport** (`lib/transport`): a WebSocket client to `VOICE_WS_URL` (import it, never edit it) that implements `call-transport.md`: `start` first (the token via the adapter in ADDENDUM §C, settings validated against the session-settings schema shape), then binary frames; handle every server event; sequence and `connectionId` fencing; stale-turn drop; heartbeat/idle; bounded reconnect with a new connection (no duplicate turns); the 10-minute cap with a warning at 9 minutes. `interrupt`, `mute`, `end`, `retry`, `coaching_choice` controls.
5. **Playback** (`lib/audio`): play TTS chunks in order per `turnId`; on `interrupt` or a new learner speech start, stop immediately and drop that turn's queued audio; never play audio for a fenced or stale turn. Never claim the provider request was cancelled.
6. **Call screen:** timer, end, mute, speaker, circular avatar, genuine status (connecting / listening / thinking / speaking / coaching / reconnecting) driven only by `status` events, an optional transient transcript (never persisted, cleared at end), and a "Give me a moment" control (sends `mute`-style pause semantics per contract, or documents what it maps to).
7. **Coaching break and summary:** render `round_feedback` (≤1 strength, ≤2 improvements, a language note) with evidence chips from `evidence[]`. Every metric uses its `status`. `insufficient_evidence` shows a plain-words reason. **Filler is always the insufficient-evidence state.** Buttons: Try again, Keep talking, Skip. Retry comparison shows only the same-definition metrics both attempts have. No overall score, confidence %, pronunciation grade, or "you improved by X%" unless computed from two available values, and then labelled as an estimate.
8. **History** (`/api/history` per ADDENDUM §B): real list, an empty state, a guest state ("Sign in to keep progress"), a plain error state, and delete-recording with a confirm. A replay button appears only when `recordingId` is present and the fetch works; otherwise it is absent. No fake data anywhere. Fixture states are allowed only in tests, labelled.
9. **Errors:** map every `error` category to plain words with the retry rule from the shape. Offline, slow network (>1 s without a status → visible "still connecting"), double-click on Start (one connection only), mic taken by another app, unsupported browser.
10. **A11y:** labels on icon-only buttons, keyboard-complete flow, visible focus, `aria-live` for status and feedback, reduced-motion, sufficient contrast, and Indic-script rendering (check a Hindi and a Tamil string).
