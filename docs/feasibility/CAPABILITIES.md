from the evidence in `prompts/phase-02-provider-feasibility/evidence/`.
Machine-readable companion: [`capabilities.json`](capabilities.json),

## How to read this table

Each column is tracked **independently**. A green cell in one column says
nothing about any other column and nothing about any other row.

| Column | What a `PASSED` actually means here |
|---|---|
| `Documented` | The provider's published documentation lists this language. **Documentation only** — not account access, not a test. |
| `Credentials` | The required variable names were present in the process. Not proof of entitlement. |
| `STT observed` | A live WebSocket session accepted the audio and returned at least one `transcript` frame. Says nothing about accuracy. |
| `TTS observed` | A live synthesis returned non-zero audio bytes. Says nothing about intelligibility. |
| `TTS model / voice` | The exact model/voice pair that answered. Timbre v2.5 throughout; v3.0 was **not** used. |
| `Gemini reply language` | A live reasoning call returned text in the requested language. Says nothing about coaching quality. |
| `Coaching quality` | **NOT RUN for every row.** Nobody reviewed a reply for teaching value, correctness or tone in that language. |
| `Filler preservation` | **NOT RUN for every row.** See [DECISION.md](DECISION.md) — this is the blocking gap. |
| `Audio localisation` | **NOT RUN for every row.** |

> **API access and a synthetic roundtrip do not prove human intelligibility
> or teaching quality.** Every cell below was exercised with audio
> synthesised by our own TTS endpoint, not with natural learner speech.

## Findings that qualify the table above

### 1. A language code does not validate the language of the audio

Feeding the **English** fixture while requesting `ta-IN` returned:

```text
'ஐ ஹேவ் பீன் வொர்கிங் ஆன் திஸ் ப்ராஜெக்ட் ஃபார் அபௌட் டூ இயர்ஸ்'
```

The endpoint transcribes whatever it hears **into the requested script**.
It does not reject a mismatch and does not signal one. A `PASSED` cell is
therefore evidence that the *plumbing* works, not that a Tamil speaker's
speech was handled correctly. Nothing in this table can substitute for
per-language accuracy testing with real speech.

### 2. STT output was lowercased

Every observed `en-IN` transcript came back lowercase, for example
`'i have been working on this project for about two years'`, with
`x-format: verbatim` explicitly set and echoed by the server config.

For filler work this matters directly: a case-sensitive marker match against
recognised text would be wrong unless the casing is normalised knowingly.
Disfluency preservation was **not** proven by `verbatim`.

### 3. Filler preservation failed on the only fixture designed to test it

`spoken-filled-hesitation` was synthesised from the script
*"So um I think the timeline is, uh, probably next month."* and recognised as:

```text
'so i think the timeline is probably next month'
```

Both `um` and `uh` are **absent from the recognition output**. Two
explanations are consistent with this observation and **cannot be
separated without a human listener reviewing the rendered audio**:

1. the synthesis dropped the hesitation during text normalisation, or
2. the recogniser dropped it.

**Established:** the fillers are absent from recognition.
**Not established:** whether the fillers were present in the rendered
audio at all — the clip was not reviewed. This is **not** a finding that
the recogniser is permanently incapable of preserving a filler, and it is
not a finding that the speaker produced two hesitations.

Whichever it is, **counting filler markers in the transcript is not a
credible source of filler evidence.** This is the central blocker; see
[DECISION.md](DECISION.md).

### 4. Timbre v2.5 voices do not speak all ten languages

The matrix used each v2.5 voice's **preferred** language, exactly as the
voice catalog instructs. Timbre v3.0's 13 voices are documented as speaking
all ten; v3.0 was **not** exercised, so the "every voice speaks all ten"
claim is untested here.

### 5. Gemini reliability is not settled

One complete `STT → Gemini → TTS` turn succeeded. Across matrix runs the
reasoning call succeeded 10/11 times; Tamil returned a bounded timeout, and
later calls from the same environment alternately failed fast with a
network-category error or exceeded 150 s on a raw SDK path. The adapter now
bounds every wait, but the **underlying service reliability is unproven**
and needs a small soak before Phase 05 depends on it.

### 6. Hinglish is a mode, not an eleventh language

`hi-en` is a **TTS-only** code. STT took `en-IN` for the Hinglish row. No
code-mixed *scoring* capability was tested in any language.

## What is still unproven, stated plainly

- **Human intelligibility** of any synthesised utterance. Nobody listened.
- **Coaching quality** in any language. No reply was scored.
- **Recognition accuracy** on natural, non-synthetic learner speech.
- **Filler preservation** — actively contradicted in one fixture.
- **Any pronunciation or confidence measure.** None exists and none is proposed.
- **Any cross-language coaching pair** (practice language ≠ coaching language).
- **Browser playback, microphone capture, interruption and cancellation** in a real call.
- **Metric denominators on real audio** beyond the synthetic-boundary check.
